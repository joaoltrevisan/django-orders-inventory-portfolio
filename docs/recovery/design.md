# PostgreSQL logical recovery drill

## Assessment and scope

Starting revision: `6e6a29f`, 204 executed PostgreSQL tests and an optional worker. Existing schema restoration verifies DDL only; it does not recover rows or applied migration history. Reuse PostgreSQL 17 tools, existing owner/bootstrap role separation, isolated Compose environments and canonical schema comparison. This delivery adds an explicitly invoked logical recovery drill, not scheduled backups, WAL/PITR, global-role recovery or production disaster-recovery certification.

Use a new fictional current-schema source and a separate recovery cluster for the primary demonstration. An additional read-only drill may recover the full historical benchmark if its actual schema/migration version is reported faithfully. Restoring an older backup does not automatically upgrade it or authorize starting the latest API.

## Rules defined before implementation

- Require explicit source project/env/database and a distinct target project/env under `olist-recovery-review` (optional lowercase suffix). Resolve only the repository's default Compose file, strip inherited Compose overrides and apply literal private env assignments. Confirm real db containers/project labels and distinct private named data volumes before work. Never select an external database URI through a database-name argument; accept simple identifiers only.
- The source is read-only. A current owner-role Django client exports a REPEATABLE READ, READ ONLY PostgreSQL snapshot and keeps that transaction open. Both `pg_dump --snapshot` and canonical row fingerprints use that snapshot. Session formatting is fixed to UTC/ISO. Concurrent source writes after the snapshot are excluded from row evidence; source DDL must remain stable. Close/rollback the snapshot on success/failure. No worker/API is automatically started or stopped.
- Scope is this project's UTF-8 PostgreSQL 17 public-schema normal tables with one integer `id` primary key; reject unsupported schemas/table identities rather than silently skipping them. Include every public table, including auth/M2M/content types and `django_migrations`. Stream ID-ordered `to_jsonb(row)::text` records into SHA-256 with newline delimiters; raw rows/password hashes never enter public stdout, logs or reports.
- Store a new custom-format `database.dump`, source schema and manifest exclusively inside a new ignored `.local/recovery` bundle: directory 0700, files 0600, no overwrite or symbolic-link escape. Dump data includes Django password hashes and source rows; it stays private. No cluster role/password dump or ACL recovery is included. Custom archives can retain role-name metadata even when ownership output is suppressed; enforce `--no-owner --no-acl` at restore. Checksums prove integrity, not trusted provenance: restore only this reviewed project's trusted source/code, because PostgreSQL restore executes archive code.
- Create only random `olist_recovery_<UUID>` destination databases in the confirmed separate cluster using template0. No user-supplied destination name, overwrite, `--clean`, drop, terminate or reuse is provided. Restrict database/schema PUBLIC privileges before loading. Bootstrap creates/locks down the fresh database; nonsuperuser `olist_owner` executes `pg_restore --single-transaction --exit-on-error --no-owner --no-acl`. Retain fresh databases and private partial artifacts on failure for inspection; never remove existing data.
- Verify all restored table counts/digests/max IDs and migration rows against the captured snapshot. Create a second fresh schema-only reference database, reparse the source DDL identically, and compare normalized re-dumps including CHECKs/FKs/indexes/functions/triggers. Only dump headers/random safety tokens/blank lines are normalized; do not strip casts or constraints to conceal mismatches.
- Sequence state is not governed by the shared MVCC snapshot. Report this explicitly and separately check positive-increment noncycling next-ID safety above restored maximum IDs and within bounds. Do not promise exact concurrent live sequence equality or consume sequence values to test them. Captured table equality does not include PostgreSQL internals, cluster globals or index statistics.
- Source Django password hashes are preserved unchanged. Newly generated target demo credentials do not become restored account passwords. A new target has independently provisioned database role passwords and Django signing secret; reapply database CONNECT/schema/table grants deliberately only after verification and any required migrations. Do not reset restored passwords or infer authentication from a checksum alone.
- Emit only sanitized public evidence: versions, counts/digests, schema hashes, migration names, sequence-safety checks, dump checksum/size, exact generated database identities and phase outcomes. Private envs, dump/schema/manifest contents and raw errors stay outside Git. Errors must not print raw SQL, row payloads, DSNs or passwords. A failed or incomplete capture is never reported as passed or reused automatically.
- Current image/API label becomes 1.4.0 for reproducible tooling; no dependency/model/migration/HTTP route/source-analysis change is intended. Existing environments are not upgraded. Recovery copies stay isolated, workers remain disabled and no RPO/RTO/PITR/high-availability guarantee is inferred from one local drill.

## Required verification

Test snapshot stability with controlled separate PostgreSQL connections (commit a later source row, prove capture excludes it), deterministic full-row hashing, auth/migration inclusion, sequence safety and unsupported identity refusal. Test private-output/target guards, exclusive file creation, corruption detection and fail-closed reports. Demonstrate actual custom dump plus restored data/DDL equality on separate clusters, preserving source and all earlier environments. Optionally repeat with actual historical data and disclose its schema version.

Run the full PostgreSQL suite, roles, strict OpenAPI and unchanged current-schema restoration; retain real recovery artifacts/evidence and independent review before publication. Hosted CI must identify its actual tested revision. Stop after this bounded delivery for technical review.

Reference semantics: [pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html), [pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html) and [snapshot synchronization](https://www.postgresql.org/docs/17/functions-admin.html#FUNCTIONS-SNAPSHOT-SYNCHRONIZATION).
